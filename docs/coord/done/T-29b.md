why_hidden_rather_than_empty: |
  The prompt forbids an empty panel and a "no task" label, and the reason is worth
  keeping: an empty frame still reads as something the player is missing out on,
  and a label saying there is no task draws attention to an absence that is by
  design. Stage four simply has no task row.
  Implemented by hiding the panel node itself rather than blanking its labels, so
  there is no path by which stale text could remain readable. readings() returns
  an empty dictionary when hidden, so a caller cannot render blanks either.
skip_behaviour: |
  Skipping withdraws the entry for the rest of that stage and does nothing else.
  Nothing in the flow waits on a minigame, which is why the notice on the entry
  can say so plainly rather than hedging.
  A run resolved elsewhere, through T-19a, withdraws the entry the same way. The
  panel listens for minigame_exited rather than assuming its own skip button is
  the only way a task can end.
