how_release_is_guaranteed: |
  GDScript has no finally block, so the release is layered three deep and each
  layer is independent of the others.
  1. Events. The normal path. birth_sequence_completed and birth_rolled_back both
     reopen input, and docs/BIRTH_STATES.md guarantees the machine reaches one of
     them from every non-terminal state.
  2. A watchdog in _process. Covers a machine that hangs without emitting either.
     The ceiling is operations.ui.input_lock_timeout_sec.
  3. _exit_tree and NOTIFICATION_PREDELETE. Godot calls _exit_tree whenever a node
     leaves the tree, including as part of being freed, and sends
     NOTIFICATION_PREDELETE immediately before deletion. Between them they cover a
     lock torn down while still closed, which is the case the first two layers
     cannot see. These are the closest thing the language has to a destructor,
     and they are what makes the guarantee real rather than hopeful.
  All three were exercised, not just described: the event path on both the
  completion and the rollback branch, the watchdog by holding a lock that nothing
  would ever complete, and the teardown path by freeing a node while it was
  closed.
how_controls_opt_in: |
  A control joins the group "birth_lockable" and never thinks about the lock
  again. That is the whole contract. The lock keeps no list of its own and needs
  no registration API, which is what lets the public surface stay at one mutator.
  Prior interactive state is remembered per control and restored on release,
  rather than blanket-enabling everything. A button that was already disabled for
  its own reasons stays disabled afterwards; this was verified rather than
  assumed.
  A non-BaseButton in the group is reported by name in a [LOCK] warning, because
  the lock can stop it responding but cannot make it look disabled, and a control
  that silently swallows input is exactly what the prompt forbids.

balance_key_added: |
  operations.ui.input_lock_timeout_sec = 60.0, in seconds, documented in the
  chapters section of docs/BALANCE_VALIDATION.md.
  The prompt requires the timeout ceiling to be read from Balance and no such key
  existed. It was added by ACCOUNT_C under the same explicit authorization the
  project owner gave for the birth sequence timings, and is recorded here rather
  than slipped in. docs/BALANCE.json is owned by T-06.
  The value has to sit above the birth sequence budget or the watchdog would fire
  during a healthy run: the sequence is 45000 ms and measures about 44947 ms in
  practice, so 60 seconds leaves roughly 15 seconds of grace. It is a safety
  ceiling, not a gameplay parameter, and nothing about the game changes if it is
  retuned.
  If a missing or non-positive value is configured, the watchdog disables itself
  and says so, leaving the event and teardown layers in place. It never falls back
  to a number baked into the script.
