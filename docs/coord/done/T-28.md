a_defect_this_task_found_in_itself: |
  The first acceptance run reported stage one as unselectable while
  enter_replay(stage_origin) succeeded on the same object, which is a
  contradiction rather than a preference.
  rebuild() was freeing the old buttons with queue_free, which is deferred. The
  old node was still holding its name when the replacement was added, so Godot
  silently renamed the new node and get_node("Replay_<stage>") returned the
  stale, disabled one. Any caller inspecting the list after a rebuild would have
  been handed the wrong button.
  The buttons are now removed from the tree before being freed, so the name is
  released immediately. Worth recording because the symptom looked like a
  selectability bug and was a node lifetime bug.
