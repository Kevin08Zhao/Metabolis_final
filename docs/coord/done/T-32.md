why_remove_and_free_rather_than_queue_free: |
  The prompt requires that two main scenes are never resident together.
  queue_free defers deletion to the end of the frame, so for that frame both the
  outgoing and the incoming scene would be in the tree, both processing and both
  receiving input. The router removes the outgoing scene from the tree and frees
  it before instancing the next one, and resident_scene_count() is public so a
  test can assert the invariant instead of taking the code path on trust.
  This is the same lesson T-28 learned the hard way, where deferred freeing let a
  stale button keep its name and be handed to a caller.
chapter_select_gating: |
  The entry appears only when a finished stage has a snapshot that
  SaveManager.can_replay_stage accepts. Offering it on the strength of progress
  alone would open a list with nothing selectable, which is a worse outcome than
  hiding the entry.
  This was tested both ways: with a sound snapshot the entry appears, and with the
  only finished stage's snapshot stripped to one carryover field it disappears
  again.
