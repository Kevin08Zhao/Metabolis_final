locking_rules_as_implemented: |
  Two reasons exist and lock_target refuses everything else:
    off_stage  a target the current stage has no use for. Recomputed once per
               stage from configuration and held for the whole stage.
    demo       every target except the one being demonstrated, for the
               demonstration's duration only.
  Two targets are in PROTECTED_TARGETS and are refused by lock_target for either
  reason: build_candidate_cards and resource_allocation_entry. The refusal is in
  the single function that closes a target, so a future table row cannot lock
  them by mistake, and the acceptance run calls it directly to confirm.

  Off-stage locking is not written per stage. Each target carries a relevance
  path, and a target whose path resolves to null or empty for the current stage
  is irrelevant to it. In practice exactly one lock results, and it results
  without this script knowing which stage it is: chapters.stage_birth.minigame_id
  is null, so stage four closes the task entry and the other three stages do not.

a_real_bug_the_harness_caught: |
  The first acceptance run failed 11 checks, and the cause was not in the guidance
  logic. Three table rows ride phase_changed - the stage completion and the
  triggers for the operation decision and the stage advance - and the first
  implementation connected the event once per row using
  Callable(self, "_relay2").bind(key).
  Godot compares two Callables produced by bind without looking at the bound
  arguments, so the second and third connections were rejected as duplicates of
  the first. Two of the six action guides therefore never triggered at all.
  The fix groups rows by event and connects each event exactly once, dispatching
  inside the handler to every row waiting on it, with a fresh lambda per event
  because lambdas compare by identity. The re-run passes.
  Recording it because the failure mode is silent in ordinary use: the connection
  error goes to push_error and the feature simply does less than it claims.
