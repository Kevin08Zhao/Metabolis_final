## 可复制执行提示词

```text
你是 Metabolis（Godot 4.7 / GDScript）的实现工程师。目标仓库：Kevin08Zhao/Metabolis_final，本地路径以当前 workspace 为准。

【任务性质】
上一版同类改良效果差，主要因为需求表达散乱。请严格按本提示词的优先级、验收标准与约束执行，不要自行扩大范围、不要重做已达标的玩法循环。

【产品一句话】
人体即城市：四个身体系统页构成可切换地图；玩家在限定施工区内摆放 6×6 系统建筑，铺设正交运输路，完成交付解锁下一系统。视觉上要像一座可读、贴地、有生活感的真实城市，而不是贴图漂浮在背景上。

【必须先读的现有文档与代码】
1. docs/SYSTEM_MAP_MODE.md
2. docs/VISUAL_COHESION_GUIDE.md
3. docs/PIXELLAB_PIPELINE.md
4. docs/ASSET_SPEC.md（若存在）
5. src/game/system_city_prototype.gd + system_city_prototype.tscn
6. src/world/build_tool.gd、route_tool.gd、cohesive_map_visuals.gd
7. art/maps/system/、art/buildings/system/、art/props/system/、art/vehicles/system/、art/tiles/organic/road_v3_transparent/

核心入口：SystemCityPrototype（route: system_city）。地图不是 Godot TileMap，而是 40×20×16px 网格上的自定义 Control._draw() + 精灵。

四个系统地图（顺序固定）：
| id | 名称 | 地图 | 建筑 | 载具 |
| system_nutrition | Nutrient Exchange | art/maps/system/map_nutrient_system_warm.png | building_nutrient_depot.png | vehicle_nutrient_delivery.png |
| system_circulation | Circulatory System | map_circulation_system_warm.png | building_circulation_station.png | vehicle_circulation_freight.png |
| system_neural | Nervous System | map_neural_system_warm.png | building_neural_dispatch.png | vehicle_neural_courier.png |
| system_respiratory | Respiratory System | map_respiratory_system_warm.png | building_respiratory_terminal.png | vehicle_oxygen_tram.png |

技术硬约束（不可破坏）：
- Godot 4.7，正交俯视 2D（非等距）
- 画布 800×450；可玩地图 640×320，原点约 (0,40)；右侧 160px 控制栏
- 网格 40×20，格宽 T=16；系统建筑 footprint 6×6（96×96）
- nearest 过滤、整数缩放；道路贴图周围必须透明，避免盖住背景地图
- 调色板锁定（art/palette.gpl / 既有 warm peach–coral–cyan 体系）
- art/ 在 Godot 工程根 src/ 之外，经 AssetLoader 以 res://../art 加载
- 不要引入真正的等距透视；不要把主玩法改回旧章节 slide 流

────────────────────────────────
一、四个地图的背景城市规划（最高优先级）
────────────────────────────────
目标：每张图的“城市可读性”必须一眼成立——主干道、街区、施工区、出入口门闸层次清晰，并模拟真实城市道路网络（正交干道 + 环绕施工区的街区回路），而不是装饰性乱线。

对 CITY_LAYOUTS（或等价数据）逐图验收并改良：
1. 每图 2–3 条连续主干道（avenues），形成环绕中央开发地块的可读环路/脊柱。
2. 四图规划必须彼此可区分（参考 SYSTEM_MAP_MODE.md 的 district 差异）：
   - Nutrient：双层市集环 + 西侧商店 / 东侧通讯角
   - Circulatory：三干道泵区 + 下方长货运街
   - Neural：信号网格脊柱 + 东侧邻里环
   - Respiratory：外围交换林荫道 + 下方宽交通街
3. 在背景中加入城市基础设施 props（电话亭、商店、候车棚、路灯等），位置避开 build_zone 与关键门闸；要有地面垫层/阴影，禁止浮空。
4. 背景道路与玩家可画道路在视觉上同属一套道路语言（现有 road_v3_transparent + connectivity mask），衔接处不得出现断层、重叠脏边或“路浮在组织上”。
5. 背景地图 PNG 若与矢量道路/props 冲突：优先调整 layout/props/遮罩绘制；仅在必要时用 PixelLab 重生成/修补地图，并保证四图风格统一。

────────────────────────────────
二、城市生活动画（背景氛围，非玩法实体）
────────────────────────────────
目标：地图“活着”，但不干扰建造与运路。

1. 市民：细胞拟人化或其他人体相关像素角色（优先精灵动画，而不是纯程序色块火柴人）。沿 citizen_lane（或等价路径）循环行走。
2. 运行车辆：市政维护车 / 轻型交通沿 vehicle_loop 循环；与玩家交付载具区分开（体型、配色或标识）。
3. 规则：
   - 不消耗资源、不阻挡放置、不抢门闸、不改变解锁逻辑
   - 贴地：脚底/车轮对齐道路中心线；有轻微阴影
   - 动画流畅：无闪烁、无瞬移、路径闭合平滑；帧率稳定
4. 若缺素材：用 PixelLab 生成 walk-cycle / 小车侧视或俯视一致的一套，写入 art/ 合理子目录并接入 AssetLoader 命名规范。

────────────────────────────────
三、玩家手动摆放建筑：施工区、缓冲、完工适配
────────────────────────────────
目标：建造感觉像“在城市空地上施工”，完工后街区自动适配摆放位置。

1. 施工区（build_zone）
   - 仅允许在适度自由的 civic parcel 内网格吸附放置 6×6 设施
   - 范围要足够给出多个合法落点，但不能吞掉主干道、商店、居民路径、边界门闸的可读性
   - 放置预览：合法绿 / 非法红；越界、撞 blocked_cells、压住关键道具均非法

2. 施工过程（必须有缓冲完成时间）
   - 确认放置 → 扣费 → CONSTRUCTING 缓冲（保持约 3 秒量级，可微调但必须可感知）
   - 施工动画：从地面升起/脚手架/工人/进度条（可强化现有 _draw_construction_animation，但观感应完整）
   - 缓冲结束前不可当运营建筑使用；取消/移动规则保持现有经济一致性（未提交可移动并退费等）

3. 完工后的环境适配（相对落点动态生成，禁止写死单一坐标装饰）
   - 建筑脚下 civic plaza / 接驳 apron 必须贴合背景地面
   - 建筑四周铺装、短引路、与最近 avenues 的衔接要根据 origin 重算
   - 右侧输出港、左侧服务港与 RouteTool 起点必须落在贴地道路上
   - 玩家画出的运输路与背景干道交汇处要视觉连续（同套路砖 + mask）

4. 风格一致性
   - 背景固有建筑/props 与玩家放置的系统建筑：同一像素语言（描边、饱和度、光源方向、俯视角度、体量比例）
   - 玩家建筑的“屏幕占位角度/大小”应与放置预览一致，禁止完工后突然缩放、旋转或错锚点
   - 锚点：建筑贴底居中；道路格贴顶左；全体禁止浮空

────────────────────────────────
四、道路与运输：贴地、可读、不破坏交付循环
────────────────────────────────
1. 玩家道路：正交绘制，从设施输出港到右边界 EXIT gate；提交成本与解锁链保持可用。
2. 道路与建筑、props、车辆全部贴合地面；禁止“路砖悬浮”“建筑悬空”“车在虚空跑”。
3. 交付动画、跨图门闸淡入淡出、下一图解锁流程必须回归测试通过。
4. 已完成路线可保留环境交付车来回，证明网络在工作。

────────────────────────────────
五、像素资产与 PixelLab（缺什么补什么）
────────────────────────────────
1. 允许且鼓励用 PixelLab 补齐/重做：地图局部、props、市民 walk、施工相关、道路衔接所需贴图。
2. 必须遵守：docs/PIXELLAB_PIPELINE.md、锁定调色板、透明底、命名规范、binary alpha。
3. 生成后要“摆放自然融洽美观”：统一光源、统一轮廓厚度、统一地面接触阴影；不要各素材各画一套风格。
4. 把 PixelLab ID、本地路径、用途记入 docs（更新 SYSTEM_MAP_MODE.md 或 VISUAL_COHESION_GUIDE.md 的资产表）。
5. 不要把候选图留在 candidates/ 却不接入；接入后删除或移走无效临时文件。

────────────────────────────────
六、明确不要做的事
────────────────────────────────
- 不要重写整个游戏架构或改回旧 organ chapter 主流程
- 不要把地图改成等距或 3D
- 不要让氛围 NPC/车成为可点击玩法或战斗单位
- 不要为了“热闹”堆满遮挡施工区的 props
- 不要引入未锁定的新主色（尤其是通用 AI 紫渐变风）
- 不要 force-push；不要提交密钥；不要改无关文件（如无故大改 project.godot）

────────────────────────────────
七、实现顺序（必须按序）
────────────────────────────────
A. 审计现状：四图 CITY_LAYOUTS、build_zone、施工动画、道路贴地、氛围人/车，列出缺口清单
B. 先修布局与贴地（道路/阴影/锚点/施工区），再补 props
C. 强化施工缓冲动画与完工动态适配（plaza/apron/引路）

F. 试运行与回归
G. 提交并发布

────────────────────────────────

【成功标准一句话】
玩家应感觉自己在四座规划清晰的身体城市里、于划定工地内施工建站；路与楼贴地生长并接上真实街网；街上有细胞市民与车辆在跑；整体像素风格统一、动画顺畅——而不是“背景画 + 悬浮摆件”。
```
